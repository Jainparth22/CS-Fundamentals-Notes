# Machine Learning: 20 Most-Asked Questions

**Q1. Supervised vs unsupervised vs reinforcement learning?**
Supervised learns from labelled data (classification, regression); unsupervised finds structure in unlabelled data (clustering, dimensionality reduction); reinforcement learns actions from rewards.

**Q2. Why split into train, validation and test sets?**
Train fits parameters, validation tunes hyperparameters and picks models, test gives one unbiased final estimate. Touching the test set repeatedly leaks information.

**Q3. What are overfitting and underfitting, and how do you fix them?**
Overfitting: great training score, poor validation score. Fix with more data, regularisation, simpler model, early stopping, dropout, cross-validation. Underfitting: poor on both; add capacity or better features.

**Q4. Explain the bias-variance trade-off.**
Bias is error from overly simple assumptions; variance is sensitivity to the training sample. Simple models have high bias/low variance, complex ones the opposite. The goal is the sweet spot with lowest validation error.

**Q5. L1 vs L2 regularisation?**
L2 (Ridge) shrinks weights smoothly; L1 (Lasso) drives some to exactly zero (feature selection). Elastic Net mixes both.

**Q6. What is cross-validation and why use it?**
Split data into k folds, train on k-1 and validate on one, rotating; gives a more reliable estimate and helps model selection. Use stratified folds for imbalance and time-series splits for temporal data.

**Q7. How do you handle class imbalance?**
Class weights, resampling (undersampling, oversampling, SMOTE inside training folds), threshold tuning, better metrics (PR-AUC, Macro F1), and collecting more minority data. SMOTE can hurt in high-dimensional sparse features.

**Q8. Precision, recall, F1: when does each matter?**
Precision matters when false positives are costly (spam); recall when false negatives are costly (disease); F1 balances both. Accuracy misleads on imbalanced data.

**Q9. ROC-AUC vs PR-AUC?**
ROC-AUC measures ranking quality across thresholds and can look good on imbalanced data; PR-AUC focuses on the positive class and is more informative when positives are rare.

**Q10. What is data leakage and how do you prevent it?**
Information from outside the training data influences the model (scaling on all data, target-derived features, future data, duplicates across splits). Fit preprocessing inside the cross-validation pipeline and split by time or group when needed.

**Q11. How do you handle missing values and categorical features?**
Missing: drop, impute (median/mode/model), add a missing indicator. Categorical: one-hot, ordinal, target encoding (carefully), hashing for high cardinality; tree models can handle some natively.

**Q12. Which models need feature scaling?**
Distance- and gradient-based models (k-NN, SVM, linear/logistic regression, neural nets, PCA, k-means). Tree-based models do not.

**Q13. How does a decision tree work and what is its weakness?**
Recursively splits data on features to reduce impurity (Gini/entropy). It overfits easily and is unstable; ensembles fix this.

**Q14. Random forest vs gradient boosting?**
Random forest bags many deep trees on bootstrap samples with random features and averages them (reduces variance). Gradient boosting adds shallow trees sequentially to correct previous errors (reduces bias) and often wins on tabular data but needs more tuning.

**Q15. What is stacking and how do you avoid leakage in it?**
A meta-model learns from base models' predictions. Use out-of-fold predictions for the meta-features so the meta-learner never sees predictions made on a model's own training rows.

**Q16. How does gradient descent work?**
Iteratively move parameters opposite to the gradient of the loss, scaled by the learning rate. Variants: batch, stochastic, mini-batch; optimisers like momentum and Adam adapt steps.

**Q17. How does k-means work and how do you choose k?**
Assign points to the nearest centroid, recompute centroids, repeat until stable. Choose k with the elbow method, silhouette score or domain needs; scale features first.

**Q18. What is PCA and the curse of dimensionality?**
PCA projects data onto orthogonal directions of maximum variance to reduce dimensions. The curse: in high dimensions distances become less meaningful and data gets sparse, so models need more data and regularisation.

**Q19. How do you explain a model's predictions and measure feature importance?**
Coefficients for linear models, permutation importance, SHAP values, partial dependence plots. Tree impurity importance is biased toward high-cardinality features.

**Q20. A deployed model's performance dropped. How do you debug it?**
Check data drift and schema/pipeline changes, label delay and quality, upstream feature bugs, training-serving skew, seasonality; compare recent data to training data, roll back if needed, then retrain with fresh data and add monitoring.
